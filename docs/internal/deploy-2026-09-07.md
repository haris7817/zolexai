**Two machines, and they carry different halves.** The VPS builds the API and
the web app, so it is the only thing that puts Text to Video HD in the
catalogue. Everything else today — automatic dialogue, the Character
Replacement exposure clause — is worker code and prompt text, and lives on
the GPU node. Neither half needs the other to be correct, so they can be done
in either order.

## Part 1 — the GPU node (worker code)

Run from the dev machine, in Git Bash, from `E:\zolexai`.

```bash
cd /e/zolexai
git fetch origin dual-engine-benchmark-prep
git status --short                     # expect clean
git rev-parse --short HEAD             # expect 2c4a621 or later

NODE="-i $HOME/.ssh/zolexai_vast -p 20577 root@163.182.37.67"

# The node's /workspace/zolexai is a file copy, not a checkout, so the
# committed tree is shipped as an archive. `.venv` is not in the archive and
# tar does not delete what it does not carry, so the environment survives.
git archive HEAD apps/worker benchmarks/client-pack \
  | ssh $NODE "tar -x -C /workspace/zolexai && echo extracted"

ssh $NODE "supervisorctl restart zolexai-worker && sleep 8 && supervisorctl status zolexai-worker"
```

**Verify the node — the code, the switches and the writers:**

```bash
ssh $NODE "grep -E '^(WORKER_NAME|RUNTIMES|AUTO_DIALOGUE_ENABLED)=' /workspace/zolexai/.env.gpu-worker
grep -c '^CEREBRAS_API_KEY=.\+' /workspace/zolexai/.env.gpu-worker
cd /workspace/zolexai/apps/worker && ./.venv/bin/python -c \"
from worker.comfy.ltx_prompts import CHARACTER_REPLACEMENT_EXPOSURE, CHARACTER_REPLACEMENT_NEGATIVE
```

Expected: `RUNTIMES=ltx,ltx_comfy,character_replacement,ltx_hd`,
`AUTO_DIALOGUE_ENABLED=true`, the key count `1`, the HD adapter named, both
booleans true, and the writer chain `['cerebras', 'gemma']`.

## Part 2 — the VPS (api + web)

On the VPS, **as root**. Git runs only as the `zolexai` user through
`runuser`, because root has no GitHub key.

```bash
cd /opt/zolexai
COMPOSE="docker compose --env-file /opt/zolexai/.env -f infrastructure/compose/docker-compose.prod.yml"

# Where we are, and the image ids to compare against afterwards.
runuser -u zolexai -- git log --oneline -1
$COMPOSE images api web

# The deploy overlay rewrites the workflow YAML in place, so its edits are
# discarded before fetching rather than stashed. NEVER `git stash push -u`
# here: it sweeps the untracked compose file and minio-cors.xml into the
# stash, and the build then fails in a way that looks unrelated.
runuser -u zolexai -- git checkout -- workflow-definitions
runuser -u zolexai -- git fetch origin dual-engine-benchmark-prep
runuser -u zolexai -- git checkout -B dual-engine-benchmark-prep FETCH_HEAD
runuser -u zolexai -- git log --oneline -1          # expect 2c4a621 or later

# Re-apply the client-test overlay and check it landed.
runuser -u zolexai -- bash deploy/vps-local.sh --profile client-test
runuser -u zolexai -- bash deploy/vps-local.sh --profile client-test --check

# Rebuild. This is the slow step, five to ten minutes depending on cache.
$COMPOSE build api web
$COMPOSE up -d --no-deps --force-recreate api web
$COMPOSE ps api web
$COMPOSE images api web                              # image ids MUST have changed
```

**Verify the live API serves the new tool:**

```bash
curl -s https://zolexai.com/api/v1/workflows | grep -o '"id":"text-to-video-hd"'
curl -s https://zolexai.com/api/v1/workflows | python3 -c \
  "import sys,json; d=json.load(sys.stdin); print([w['id'] for w in (d.get('workflows') or d)])"
```

The first must print `"id":"text-to-video-hd"`. The second lists every tool
the client will see.

## What to expect afterwards

**Text to Video HD** appears alongside the existing tools: 1920×1080 with
sound, 8 and 15 seconds, 16:9. A 15-second render takes about five minutes of
GPU. Thirty seconds is deliberately not offered — it renders fine but blocks a
one-job-at-a-time node for 17 minutes.

**Automatic dialogue** is on for this node only. A prompt with people in it
and no quoted words now gets a short written exchange, and the video speaks
it. A prompt saying "no dialogue" still gets silence, and a prompt that
already contains quoted words is left alone. It paraphrases rather than
delivering the lines verbatim — see `auto-dialogue.md`.

**Character replacement** carries the client's exposure lock and their
directional darkening terms. Three GPU pairs say the exposure lock changes
nothing detectable — the drift between seeds swings wider than the clause
moves it, and one run brightens. It stays on because the client asked and it
does no measured harm, but it is not a fix and should not be described as one.
See `character-replacement-darkening.md`.

## The switches, if something looks wrong

None of these need a rebuild. Edit `/workspace/zolexai/.env.gpu-worker` on the
node and `supervisorctl restart zolexai-worker`.

| symptom | switch |
| --- | --- |
| videos talking when they should not | `AUTO_DIALOGUE_ENABLED=false` |
| character replacement looks worse | `CHARACTER_REPLACEMENT_EXPOSURE_CLAUSE=false` |
| HD tool misbehaving | drop `ltx_hd` from `RUNTIMES` |

Rolling the VPS back is `git checkout -B <old branch> <old sha>`, the overlay
again, and the same build. The old image ids from the first `$COMPOSE images`
are what to compare against.
